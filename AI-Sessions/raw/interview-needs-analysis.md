## 1부. 핵심 요약

인터뷰가 말하는 방향(확인 → 발견 → 행동 안내)과 BizPedia의 설계 원칙은 이미 같다.
달라져야 할 것은 **다루는 영역, 첫 가치를 주는 입구, 차별점의 위치**다.

### 1.1 결론 12개

| # | 결론 | 근거 | 태그 |
|---|---|---|---|
| C01 | 방향은 유지한다. "확인 → 발견 → 행동"은 기존 설계의 집계 불가 판정·화이트리스트·출처 배지·승인 흐름과 같은 철학이다 | 4부 G01 | `[설계문서]` |
| C02 | 모든 업종이 들어올 수 있는 입구로 **1분 진단**(선택형 6문항 + 조건부 1문항 + 선택 1문항, LLM 없음, 8.4)을 둔다 | 발주는 외식업에만 맞음. 인터뷰 예시에 미용업 | `[제안·미확정]` |
| C03 | 매일·매주 쓰는 이유는 업종별로 다르게 둔다. 외식업은 발주, 직원 있는 곳은 알바 급여 계산. **매출 직접 입력을 주력으로 삼지 않는다** | 캐시노트 등 카드매출 자동연동 앱이 포화 | `[확인됨]` S41~S44 |
| C04 | 차별점은 "세금 알림"이 아니다. **세금·교육·노무·업종 의무·지원금을 내 가게 기준 기한으로 한 화면에 모으고, 챙겼는지 체크를 남기고, 출처를 붙이는 것**이다 | 국세청이 이미 카카오톡으로 신고 안내 | `[확인됨]` S14 |
| C05 | 외식업 전용 강점 후보: **발주 품목(면세 농산물) → 의제매입세액공제 증빙(계산서·카드) 챙기기 안내** | 인터뷰 "매입계산서 안 챙김"과 직결 | `[확인됨]` S10 / `[가설]` |
| C06 | 바로 만들 수 있는 것: 세금·교육 기한 규칙, 5인 기준 비교표, 알바 급여·4대보험·순이익 계산기, 고객 응대 문구, 용어·절세 설명 | 외부 연동 없이 규칙·계산·콘텐츠로 가능 | `[제안·미확정]` |
| C07 | 알림 채널은 "바로"가 아니라 **조사 항목**이다 | 구글 캘린더 모바일 .ics 미지원, iOS 웹푸시 제약, 카카오 요건 불명확 | `[확인됨]` S45~S47 |
| C08 | 장부 검증·세금 적정성·과다납부 확인은 **보류**한다 | 홈택스·카드·은행 연동 필요 + 세무사법 분쟁 사례 | `[확인됨]` S38 |
| C09 | 정부지원은 자체 추천기를 만들지 않는다. 진단 결과에서 1~2건 발견해 기업마당·보조금24로 연결하고, **두루누리**를 첫 후보로 둔다 | 보조금24가 소상공인 맞춤 조회 제공, 기업마당 API 존재 | `[확인됨]` S25, S32, S34 |
| C10 | 수익 모델에서 **전문가 연결 수수료·지원금 신청 대행은 제외**한다. 구독(알림·리포트·기록)과 B2G·제휴를 가설로 둔다 | 세무대리 소개·알선 고발 사례, 정책자금 브로커 처벌 법제화 추진 | `[확인됨]` S36~S39 |
| C11 | 9월 코드 범위는 유지하고 **스키마만 선반영**한다. 예비창업자 9월 모순은 해소가 필요하다 | 9월 버퍼 없음. 예비창업자는 9월에 쓸 기능이 없음 | `[설계문서]` D01, D06 |
| C12 | 인터뷰 표본 정보를 보강하고, "발주 불편이 없다"는 가설을 추가 인터뷰로 확인한다 | 정리본이 범주를 미리 정해 구성됨 | `[가설]` |

### 1.2 제안 구조 — 3층

| 층 | 이름 | 대상 | 주기 | 사장님 입력 | 사장님이 얻는 것 | 기존 설계 재사용 |
|---|---|---|---|---|---|---|
| ① | 1분 진단 | 전 업종 + 예비창업자 | 가입 직후 1회, 연 1회 갱신 | 선택형 6~7개 | 올해 챙길 신고·교육·노무 의무, 받을 수도 있는 지원 | `duties`, `app_users.status`, 칩 버튼, 출처 배지 |
| ② | 습관 | 외식업 / 직원 있는 곳 / 전 업종 | 매일·매주·매월 | 발주 문장 / 근무시간 / 월 숫자 4개 | 발주 문구, 알바 급여, 남은 돈, 기한 체크 | 발주 도메인 전체, `orders` |
| ③ | 연결 | 판단이 필요한 사장님 | 필요할 때 | 없음 | 세무사·노무사에게 물어볼 목록, 공공 서비스 링크 | 웹 폴백 배지 원칙 |

### 1.3 이 부의 핵심

| # | 핵심 |
|---|---|
| 1 | 방향은 같고, 입구(1분 진단)와 차별점(한 화면 통합 점검)이 바뀐다 |
| 2 | 매출·세금 예상은 경쟁이 치열해 주력으로 삼지 않고, 교육·노무·업종 의무와 발주 연계를 강점으로 삼는다 |
| 3 | 알림·정부지원·수익 모델은 1차 답변보다 보수적으로 판단한다 |

## 2부. 인터뷰 원문 정리

사용자가 전달한 인터뷰 정리본을 표로 복원했다. **문장은 바꾸지 않았다.**

### 2.1 인터뷰 개요 (원문)

| 항목 | 원문 |
|---|---|
| 제목 | 소상공인 주요 니즈 및 필요 기능 정리 |
| 범위 | 소상공인을 대상으로 사업 운영 과정에서 실제로 궁금한 점, 제대로 관리되고 있는지 확인하기 어려운 부분, 자주 놓치거나 번거롭게 느끼는 업무, 그리고 있었으면 좋겠다고 생각하는 기능에 대한 내용 정리 |
| 구성 기준 | 특히 세금·절세, 회계·장부, 매출 및 순이익 관리, 직원·노무, 필수 교육 및 의무사항, 정부지원, 고객 응대 등 사업 운영 과정에서 겪는 주요 어려움과 놓치거나 불필요한 손실을 줄이기 위해 필요한 기능을 중심으로 구성 |

### 2.2 니즈·기능 표 (원문 복원, 27행)

| ID | 구분 | 소상공인이 궁금한 점 / 불편한 점 | 있었으면 좋겠는 기능 |
|---|---|---|---|
| I01 | 세금·세무 일정 | 부가세, 종합소득세 등 어떤 세금을 언제 신고해야 하는지 헷갈림 | 사업자 유형별 세금 일정 캘린더 |
| I02 | 세금·세무 일정 | 간이과세자와 일반과세자의 신고 일정·방법 차이가 복잡함 | 과세유형 선택 시 해당 세금만 맞춤 안내 |
| I03 | 세금·세무 일정 | 신고 시기를 자주 놓치거나 그때그때 연락을 받고 처리함 | 신고 전 자동 알림·리마인드 |
| I04 | 회계·장부 검증 | 현재 장부가 제대로 작성되고 있는지 스스로 판단하기 어려움 | 매출·매입·비용 데이터를 기반으로 장부 이상 여부 점검 |
| I05 | 회계·장부 검증 | 실제로 들어와야 할 돈과 장부상 금액이 맞는지 확인하기 어려움 | 매출·입금·비용을 비교하는 수입/지출 검증 기능 |
| I06 | 회계·장부 검증 | 세금이 제대로 계산되어 나간 것인지 확인하기 어려움 | 신고 내역을 기준으로 세금 적정성 체크 |
| I07 | 절세 | 합법적으로 줄일 수 있는 세금을 놓치고 있지는 않은지 궁금함 | 사업자 상황에 맞는 절세 가능 항목 안내 |
| I08 | 절세 | 세금을 괜히 더 낸 것은 아닌지 확인하고 싶음 | 예상 세액과 실제 납부액을 비교해 과다납부 가능성 확인 |
| I09 | 절세 | 절세와 탈세의 차이를 일반인이 이해하기 어려움 | 합법적 절세와 주의해야 할 행동을 쉬운 말로 설명 |
| I10 | 절세 | 특히 회계·세무 용어 자체가 어려움 | 전문용어 대신 사장님 눈높이 설명 |
| I11 | 세금 예상 | 올해 세금을 얼마나 내게 될지 미리 알기 어려움 | 현재 매출·비용 기준 예상 세금 계산 |
| I12 | 필수 교육·의무사항 | 업종별 교육, 신고 등 반드시 해야 하는 것을 놓칠 수 있음 | 업종별 필수 의무사항 체크리스트 |
| I13 | 필수 교육·의무사항 | 미용업 등은 연간 위생교육을 놓치면 과태료가 발생 | 교육기한 사전 알림 |
| I14 | 매출·순이익 관리 | 매입계산서를 잘 챙기지 않는 업종은 실제 순이익 계산이 어려움 | 매출·재료비·임대료·인건비 등을 넣으면 순이익 자동 계산 |
| I15 | 매출·순이익 관리 | 매출은 알아도 실제 얼마를 벌고 있는지 파악하기 어려움 | 월별 매출·비용·순이익 대시보드 |
| I16 | 직원·노무 관리 | 직원을 처음 채용할 때 근로계약, 급여체계 등이 복잡함 | 사업장 상황별 근로계약·노무 안내 |
| I17 | 직원·노무 관리 | 5인 미만/이상 사업장의 적용 기준을 이해하기 어려움 | 직원 수에 따른 노무사항 비교표 |
| I18 | 직원·노무 관리 | 연봉제·인센티브제 등 급여제도를 어떻게 구성할지 어려움 | 급여방식별 설명 및 계산 예시 |

### 2.3 결론 (원문)

| 항목 | 원문 |

| 결론 1 | 인터뷰 결과, 소상공인의 핵심 어려움은 단순히 정보가 부족한 것이 아니라 자신의 사업이 제대로 운영되고 있는지, 무엇을 놓치고 있는지 스스로 판단하기 어렵다는 점으로 나타남. |
| 결론 2 | 특히 세금·절세, 순이익, 노무, 필수교육, 정부지원 등은 잘못 관리하거나 놓칠 경우 추가 비용, 과태료, 지원 혜택 누락 등 실제 금전적 손실로 이어질 수 있음. |

#### 8.2.4 SQL

```sql
-- 003_profile.sql (제안·미확정)
alter table app_users
  add column if not exists tax_type text
    check (tax_type in ('general','simplified','exempt','corporate','unknown')),
  add column if not exists employee_band text
    check (employee_band in ('0','1-4','5-9','10-20','21+','unknown')),
  add column if not exists has_part_time boolean,
  add column if not exists withholding_semiannual boolean,
  add column if not exists opened_band text
    check (opened_band in ('lt1y','1to3y','gt3y','not_yet')),
  add column if not exists revenue_band text
    check (revenue_band in ('lt48m','lt104m','lt150m','lt750m','gte750m','undisclosed')),
  add column if not exists region_sido text,
  add column if not exists region_sigungu text,
  add column if not exists diagnosed_at timestamptz;

alter table orders
  add column if not exists items jsonb;          -- [{name, qty, unit, category}]

alter table duties
  add column if not exists kind text not null default 'custom'
    check (kind in ('tax','education','labor','license','support','saving','custom')),
  add column if not exists rule_key text,
  add column if not exists rule_verified_on date,
  add column if not exists source_url text,
  add column if not exists remind_at timestamptz,
  add column if not exists completed_at timestamptz;

-- 규칙이 만든 항목은 (사용자, 규칙, 기한) 하나만. 기한 없는 항목도 중복 방지 (PG15+)
create unique index if not exists duties_rule_uniq
  on duties (user_id, rule_key, due_date) nulls not distinct
  where rule_key is not null;
```

|---|---|---|---|
| 놓치면 손해 | `penaltyNote` 있음 + 기한 90일 이내 `[제안·미확정]` | 홈 맨 위, 최대 3개 | 위생교육, 부가세 예정고지 |
| 다가오는 일 | 기한 있음 + 90일 초과 | 목록, D-Day 순 | 부가세 확정신고, 종소세 |
| 받을 수도 있는 돈 | kind = support 또는 saving, appliesTo true/maybe | 카드 최대 2개 | 두루누리, 노란우산 |
| 알아두면 좋은 것 | 기한 없는 안내 | 칩 버튼 | 5인 기준표, 근로계약서 |
| 확인이 필요한 것 | appliesTo = "maybe" 또는 "모름" 답변 | "이것만 확인하면 더 정확해져요" | 과세유형 확인 |

#### 8.4.4 우선순위

| 순서 | 기준 | 이유 |
|---|---|---|
| 1 | 기한이 지났거나 14일 이내 + 벌칙 있음 | 당장 손해 |
| 2 | 기한 90일 이내 + 벌칙 있음 | 준비 시간 필요 |
| 3 | 받을 수도 있는 돈 | 가치 체감 |
| 4 | 기한 90일 초과 | 알려만 둠 |
| 5 | 기한 없는 안내 | 필요할 때 |

## 9부. 화면 설계 예시 `[제안·미확정]`

모든 화면은 모바일 세로 화면 기준이다. 수치는 제안이며 실제 사용자 테스트(12부 H04)로 조정한다.

### 9.1 화면 공통 원칙
