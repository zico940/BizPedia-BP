# 10월 — 체크리스트 · 예비창업자 모드

## Summary

과태료 체크리스트와 개업 체크리스트를 만들고, 홈 화면을 모드별로 분기한다.
칩 버튼(사전 작성 답변)을 붙인다.

**9월 범위가 아니다.** 1년에 3번 쓰는 기능이라 2주로는 검증이 안 된다.

## Details

설계는 [[user-mode-design]].

### 이월한 이유

체크리스트는 리텐션을 만들지 못한다. 보건증 1년, 위생교육 1년, 소방 반기다.
9월 검증 목표는 **재방문율**이므로 매일 쓰는 발주가 우선이었다.

다만 `app_users.status`와 `duties` 테이블은 **9월에 이미 만들어져 있다.**
가입 시 "아직 준비 중" 값도 받아두었으므로 화면만 붙이면 된다.

### 작업

1. `duties` 기반 체크리스트 — `open`은 D-Day, `preparing`은 순서
2. 홈 화면 분기 (`app_users.status`)
3. 칩 버튼 — 영업용 10개 + 개업용 10개를 **손으로 작성**
4. **발주 데이터 → 의무 자동 판정** (아래)

### 발주가 컴플라이언스를 채운다 — 제품의 핵심 고리

[[bizpedia-mvp]]가 제품의 존재 이유로 든 구조다. 이게 없으면 BizPedia는
"발주 앱 + 캘린더 앱"이고, 있으면 다른 곳이 흉내내기 어려운 해자가 된다.

> 매일 쓰는 발주로 사용자를 붙잡고, **발주 데이터가 컴플라이언스를 자동으로 채운다**

9월에 발주 데이터가 쌓이므로 10월에는 재료가 준비돼 있다.

**판정 예시** (규칙 2~3개로 시작한다):

| 발주 데이터에서 읽는 것 | 자동 생성되는 의무 |
|---|---|
| 축산물(돼지고기·소고기 등) 품목 | 축산물 이력 보관 의무 |
| 발주 빈도·거래처 수로 추정한 규모 | 위생교육 대상 여부 |
| 주류 품목 | 주류 판매 관련 의무 |

핵심 효과는 **사장님이 아무것도 입력하지 않아도 체크리스트가 정확해지는 것**이다.
"내가 뭘 해야 하죠?"라고 묻기 전에 앱이 먼저 안다.

**주의**: 판정 규칙은 **화이트리스트**로 한다. LLM에게 "이 발주로 어떤 의무가 생기나"를
묻지 않는다 — 없는 의무를 지어내면 과태료보다 신뢰 손상이 크다.
근거 법령이 확인된 규칙만 넣고, 불확실하면 넣지 않는다.

### 주의

- 조회는 `order by due_date nulls last, sort`
- 칩 버튼 답변에는 🟢 배지와 출처를 단다. **근거가 없으면 "확인 필요"로 비워둔다**
- `preparing`에서는 발주 메뉴를 숨긴다 (거래처가 아직 없다)

## 완료 확인

1. `preparing` 계정 → 개업 체크리스트, 발주 숨김
2. `open`으로 전환 → 과태료 체크리스트 + D-Day
3. 칩 버튼 → 즉시 응답 + 🟢 배지
4. **축산물 품목을 발주한 계정 → 해당 의무가 `duties`에 자동 생성되는지**
5. 근거 법령이 없는 의무가 생성되지 않는지 (화이트리스트 밖은 생성 안 됨)
