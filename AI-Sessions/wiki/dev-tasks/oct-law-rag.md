# 10월 — 법령 RAG · 상권 데이터

## Summary

법령 조문을 수집·임베딩해 벡터 검색을 붙이고, 상권 집계와 집계 불가 판정을 만든다.

**9월 범위가 아니다.** 실작업 11일에 데이터 작업까지 넣으면 둘 다 껍데기가 되어
10월로 이월했다.

## Details

설계는 [[search-design]].

### 이월한 이유

법령 데이터 작업은 코드가 아니라 **사람 손이 가는 일**이다. 수집·정제·청킹에만
3~5일이 들고, 그만큼 발주 기능이 얕아진다. 9월 검증 목표(발주 재방문율)와도 무관하다.

### 작업

1. `scripts/fetch_laws.py` — 법령 API → 청킹 → 임베딩 → `law_chunks`
2. 벡터 검색 + 출처 조문 노출 + 면책 고지
3. `scripts/fetch_stores.py` — 상권 API → 정제 → `stores`
4. 집계 화이트리스트 + 대체 지표 응답

### 선행 조건

- **LLM·임베딩 제공자 확정** — 09-20에 이미 정해져 있을 것
- **발행받을 데이터 형태 확인** — 형태를 모르는 채로 파이프라인을 설계하지 않는다
- 대상 업종·지역 범위 결정

### 주의

- 청킹 크기는 제공자에 따라 다르다. Gemini는 입력 2048 토큰
- **상권 데이터를 임베딩하지 않는다.** 정형 데이터라 SQL로 다룬다
- 집계 불가 질문("카페 폐업률")은 대체 지표로 치환한다. 숫자를 지어내면 실패다

## 완료 확인

1. 조문에 있는 질문 → 답변 + 조문 번호 배지
2. "역삼동 카페 몇 개?" → 숫자
3. "카페 폐업률?" → 치환 응답 (숫자가 나오면 실패)
