# Agent Collaboration Model

## Summary

개발 에이전트끼리의 호출은 의존 관계를 따르는 허브 구조로 유지한다. backend가 frontend와
database 사이의 조율 허브이자 API 계약 문서의 소유자다. 함께 세 가지를 도입한다. 스폰 비용을
줄이는 규칙, 추측한 값이 확정된 사실처럼 퍼지지 않게 하는 표기와 검사 장치, 그리고 글로만 있던
핵심 규칙을 훅과 권한 설정으로 강제하는 장치다.

## Context

사용자가 요청한 것은 세 가지다: 에이전트 간 소통 구조 개선, 토큰 소모 최소화,
문서 기록 정확도 점검. 이어서 에이전트별 규칙과 설정 보강도 요청했다. 판단의 바탕이 된 사실은
다음과 같다.

- 서브에이전트는 `Agent` 툴로 매번 새로 스폰된다. 대화는 세션이 끝나면 사라지고 파일만 남는다.
  `Agent`는 새 하위 세션을 띄울 뿐, 자신을 호출한 상위 세션으로 되돌아가지 못한다.
- 서브에이전트는 다른 서브에이전트를 부를 수 있다. 메인 대화 아래 3단계까지다 (공식 문서로
  확인했고, backend가 frontend를 실제로 호출해 봤다).
- 하지만 frontmatter `tools`의 `Agent(...)` 목록은 서브에이전트에서 무시된다. database가 목록에
  없는 frontend를 불렀는데 막히지 않았고, 공식 문서에도 그렇게 적혀 있다. 그래서 호출 구조는
  훅으로 강제한다.
- 커스텀 에이전트가 스폰될 때 `CLAUDE.md`와 `.claude/rules/` 파일이 자동으로 로드된다.
  그런데 에이전트 정의 6종이 `dev-common.md`를 다시 읽으라고 지시하고 있어서, 같은 파일을
  스폰마다 두 번 읽고 있었다.
- 이 세션에서는 수정한 에이전트 정의와 규칙이 서브에이전트에 바로 반영되지 않았다. 문서는
  에이전트 폴더를 감시해 다시 로드한다고 설명하지만, 실제로는 반영되지 않았다. 그러니 수정한 뒤에는
  재시작해서 확인한다. 설정 파일(권한, 훅)은 세션 도중에도 다시 로드된다. `paths`로 범위를
  한정한 규칙은 해당 경로의 파일을 읽는 순간 로드된다.

## Details

### 기각한 대안

- **완전 mesh (모든 개발 에이전트가 서로 호출)**: 호출 경로가 늘수록 스폰 비용이 커진다.
  또 frontend와 database가 backend 모르게 합의하면, API 계약 문서와 어긋난 값이 두 문서에
  따로 남는다.
- **pm이 설계 문서를 모두 작성**: 구현 중에 설계 문제가 드러나도 pm과 대화할 통로가 없다.
  `Agent`가 상위 세션으로 돌아가지 못하기 때문이다. 역할별 전문성과 병렬 설계를 잃고,
  설계 문서는 구현 에이전트가 소유한다는 소유권 규칙과도 충돌한다.

### 채택한 구조

- 호출 그래프는 기존 구조를 유지한다. frontend와 database는 서로 직접 조율하지 않고 backend를
  거친다. 목록 밖 호출은 훅이 거부한다.
- database에 `git-manager` 호출 권한과 커밋 단계를 추가했다. database는 스키마를 직접
  만들면서도 커밋 단계가 없었다.
- 호출 절차는 세 단계다. 상대가 소유한 문서를 먼저 읽고, 질문은 한 번에 모아 보내고,
  합의는 호출받은 쪽이 자기 문서에 쓴 뒤 경로만 돌려준다.
- 동료 에이전트의 호출로 뜬 에이전트는 조율 답변과 자기 문서 기록만 한다. 이렇게 하면 깊이
  제한(3단계)에 걸리지 않는다. 구현·검수 중에는 문서도 고치지 않고 답변만 한다. 승인된 설계가
  재승인 없이 바뀌지 않게 하기 위해서다. 원문은 `.claude/rules/dev-common.md`의 Peer Communication에 있다.

### 강제 장치

- `.claude/settings.json`의 훅은 모두 `scripts/agent_guard.py`를 부른다.
  - 호출 허용 목록: 호출한 에이전트의 frontmatter에서 `Agent(...)`를 읽고, 목록 밖 호출을
    거부한다. 허용 목록은 frontmatter 한 곳에만 있다.
  - git 쓰기 명령: 프로젝트 에이전트 중에서는 git-manager만 실행할 수 있다.
  - 설계 잠금: 프로젝트 문서의 "승인된 설계" 절에 오른 design 문서는 프로젝트 에이전트가
    `status` 줄과 `(미확정)` 표시 말고는 Write·Edit할 수 없다. 설계를 바꾸려면 pm이 목록에서 빼고
    재승인을 받는다.
    fork 호출도 허용 목록 검사를 받는다.
  - 종료 시 린트: 자기 소유 문서나 소유자가 없는 문서에 FAIL이 있으면 한 번 되돌린다.
    `lint_wiki.py --owner`를 쓰므로, 남의 미완성 문서 때문에 막히지는 않는다.
    Bash가 없는 pm도 이 훅으로 린트를 받는다. index 미등록은 pm에게만, 모든 문서를 대상으로 검사한다.
- `permissions.ask`: `git push`, `git init`, `git reset --hard`, `rm -rf`는 누가 실행하든
  사용자 확인 창을 띄운다.
- 메인 세션과 기본 제공 에이전트는 제한하지 않는다. 훅 스크립트에 오류가 나면 막지 않고
  통과시킨다. 훅이 고장 나서 모든 작업이 멈추는 것보다 낫다고 판단했다.

### 품질 게이트

- 테스트·빌드를 통과한 것만 커밋한다. 커밋을 맡길 때는 바꾼 파일 목록을 넘기고,
  git-manager는 그 파일만 stage한다.
- 비밀값은 코드에도 하드코딩하지 않는다. 되돌릴 수 없는 마이그레이션은 사용자 승인을 받고,
  롤백 방법을 기록한다.
- pm은 code-review에 검수 범위를 지정하고, 재위임은 2회까지만 한다.

### 최적화

- 에이전트 정의에서 `dev-common.md`를 다시 읽으라는 지시를 지웠다.
- `knowledge-ops.md`는 `paths`로 범위를 좁혀, vault 파일을 다룰 때만 로드되게 했다.
- `index.md`와 `log.md`를 먼저 읽는 일은 메인 세션과 pm만 한다. `log.md`는 최근 10개 항목만 본다.
- pm은 작업 지시서를 넘긴다. 목표, 수정 범위, 확정 값과 출처, 읽을 문서가 들어간다.
  하위 에이전트의 보고에는 경로와 요약만 담는다.
- git-manager의 `omitClaudeMd` 설정은 효과가 없어 제거했다.

### 모델 배정

모두 사용자가 확정했다.

- **pm: opus.** 요구사항 정리나 작업 지시서에서 판단을 잘못하면 하위 에이전트 전체가
  재작업한다. 반면 pm은 코드를 다루지 않고 요청당 한 번 정도만 떠서 토큰 사용량이 적다.
  `inherit`는 사용자 전역 설정에 따라 결과가 달라지므로 쓰지 않는다.
- **git-manager: haiku.** 기계적인 git 작업이고, 작업 단위마다 호출돼 가장 자주 뜬다.
- **backend, frontend, database, code-review: sonnet.** 코드와 문서를 대량으로 읽고 쓰는
  에이전트라 비용과 품질의 균형을 둔다.

### 흐름 보강

규칙끼리 부딪히는 지점을 검토한 뒤 사용자가 다음을 확정했다.

- **설계와 구현을 호출 단위로 나눈다.** 서브에이전트는 세션 도중에 상위로 돌아가지 못한다.
  그래서 설계 단계 호출이 끝나면 pm이 설계 문서 목록을 보고하고, 사용자가 승인하면 구현 단계를
  따로 호출한다. 승인된 설계 문서만 `status: active`가 된다.
- **서브에이전트는 질문이 생기면 멈추고 보고한다.** pm을 포함한 서브에이전트에게는 사용자에게 묻는
  도구가 없다. 확인 항목을 프로젝트 문서에 기록하는 일은 그 문서의 소유자인 pm이 한다.
- **개발 중 `index.md`·`log.md`는 pm만 고친다.** 병렬 수정과 등록 권한 문제(code-review)를 없애기
  위해서다. 그래서 종료 시 린트(`--owner`)는 다른 에이전트에게는 index 미등록을 FAIL로 치지 않는다.
  pm에게는 모든 문서의 미등록을 FAIL로 친다.
- 보고에 커밋 해시를 넣어 pm이 code-review의 검수 범위를 정할 수 있게 한다.
- git 쓰기 훅은 `git -C`, `pull`, `apply`, `am`, `worktree`, `config`까지 막고, 읽기 전용인
  `tag -l`, `stash list`, 인자 없는 `branch`는 허용한다.

### 정확도 장치

- 확정 전 값에는 `(미확정)`을 붙이고, 결정 문서에는 `decided_by`를 둔다. 다른 에이전트
  문서의 값은 복사하지 않고 링크한다. 원문은 `.claude/rules/knowledge-ops.md`의
  Document Format에 있다.
- 린터가 FAIL로 잡는 것: 빈 frontmatter 값, 달력에 없는 날짜, `decided_by` 누락,
  없는 raw 파일을 가리키는 `source`, 인수인계 문서의 형식과 이름. WARN으로 알리는 것:
  design 문서를 링크하지 않은 dev-task, 규칙에 맞지 않는 파일명.
