# Glossary

## Summary

프로젝트에서 쓰는 용어를 한 곳에 고정한 사전이다. 같은 개념을 서로 다른 이름으로 부르면서 생기는 문서 모순을 막는 것이 목적이다.

## Context

여러 에이전트가 각자 문서를 쓰면 같은 대상을 "발주", "주문", "order"처럼 제각기 부르게 된다. 문서가 늘어난 뒤에는 어느 쪽이 맞는지 되짚기 어렵고, 코드 식별자까지 갈라진다. 그래서 용어는 이 문서 하나를 기준으로 삼는다.

## Details

용어는 누구나 추가할 수 있다. 다만 이미 있는 정의를 바꾸거나 지우려면 pm에게 보고해 승인을 받는다. 추가만 하는 것은 기존 내용과 충돌하지 않지만, 정의를 바꾸는 것은 이미 그 용어로 쓰인 모든 문서에 영향을 주기 때문이다.

### 도메인 용어

| 한글 | 영문 식별자 | 정의 |
|---|---|---|
| 발주 | order | 사용자가 물품이나 서비스를 요청해 등록하는 행위와 그 기록. 이 프로젝트에서 "주문"은 쓰지 않고 "발주"로 통일한다. |
| 발주 페이지 | order page | 발주를 등록하고 조회하는 화면. |
| 설정 페이지 | settings page | 사용자나 시스템 환경값을 변경하는 화면. |
| 로그인 페이지 | login page | 사용자가 자신을 확인시키고 서비스에 진입하는 화면. |
| 사용자 | user | 서비스를 이용하는 사람. 계정과 1:1로 대응한다 (미확정 — 사용자 범위 확인 전). |
| 계정 | account | 사용자를 식별하는 데이터 단위. |
| 인증 | authentication | 요청자가 본인이 맞는지 확인하는 절차. |
| 권한 | authorization | 확인된 사용자가 무엇을 할 수 있는지 정하는 규칙. |

### BizPedia 용어

| 한글 | 영문 식별자 | 정의 |
|---|---|---|
| 서류함 상태 | status | 사용자가 영업 중(`open`)인지 창업 준비 중(`preparing`)인지 나타내는 값. |
| AI 검색 범위 | ai_range_days | AI가 조회할 수 있는 과거 일수. 성능 설정이 아니라 보안 경계다. |
| 출처 배지 | badge | 답변이 어디서 나왔는지 표시하는 라벨. 🟢 검증됨 / 🔵 공공데이터 / 🔴 미확인. |
| 웹 폴백 | web fallback | DB에 근거가 없을 때 웹 검색으로 답하는 마지막 경로. |
| 개인 지식 | user_knowledge | 웹 폴백 결과를 저장한 것. 작성한 본인에게만 보인다. |
| 공용 지식 | law_chunks | 법령 원문에서 확인한 검증된 지식. 모든 사용자가 공유한다. |
| 집계 불가 | non-aggregatable | 보유 데이터로 계산할 수 없는 질문. 대체 지표로 치환한다. |

### 미확정 용어

확정 전 용어는 [[bizpedia-mvp#확인이 필요한 항목]]에서 한 곳으로 관리한다. 확정 전까지 문서와 코드에서 임의로 쓰지 않는다.
