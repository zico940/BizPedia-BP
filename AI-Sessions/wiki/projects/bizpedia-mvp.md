# BizPedia MVP

## Summary

소상공인 대상 컴플라이언스·발주 비서 서비스를 **2026-09-30까지** 실사용자 검증 가능한
MVP로 만든다. 추석(09-24~27)을 빼면 **실작업 11일**이다.

목표는 데모가 아니라 **사장님·예비창업자 10명에게 실제로 쓰게 해서 재사용률을 보는 것**이다.

계획 전문은 `C:\BizPedia\app\PLAN.md`에 있다. 이 문서는 vault 쪽 진행 맥락과
확인이 필요한 항목을 관리한다.

## Context

기획 원안(`설명.md`)은 세 가지 축이었다 — 과태료 체크리스트, 규제 RAG 검색, 발주 자동화.
분석 결과 기술 설계는 탄탄하나 사업 설계가 비어 있었고(수익 모델 부재, 획득 경로 부재),
무엇보다 **구조적 딜레마**가 있었다.

과태료 체크리스트는 1년에 3번 쓰는 기능이라 리텐션을 만들지 못하고, 발주는 경쟁이
포화(푸드팡·마켓보로 등)라 차별성이 없다. 그래서 **매일 쓰는 발주로 사용자를 붙잡고,
발주 데이터가 컴플라이언스를 자동으로 채우는** 구조를 목표로 삼았다.

원안 대비 주요 변경:

- 백엔드를 Python API + Next.js 두 런타임에서 **Next.js 단일 런타임**으로 (파이썬은 배치만)
- Supabase 대신 **직접 띄운 Postgres** (사용자 결정)
- HNSW 인덱스 제외 (소규모에선 순차 스캔이 더 빠르고 정확)
- 장기 기억 압축, 시맨틱 캐싱, 상권 통계 원안 용도 제외

### 타협하지 않기로 한 것

세 가지는 일정이 밀려도 버리지 않는다.

1. **개인정보 격리** — Supabase를 쓰지 않아 RLS가 자동으로 걸리지 않는다. 모든 조회에
   `where user_id = $세션유저`를 넣고, 데이터 접근을 `lib/db/queries.ts` 한 곳으로 모은다.
2. **AI 검색 날짜 범위** — 성능 기능이 아니라 보안 경계다. 범위값을 클라이언트에서 받지 않는다.
3. **집계 불가 판정** — "카페 폐업률" 같은 질문에 LLM이 숫자를 지어내지 않게 한다.
   상권 API는 스냅샷이라 시계열 계산이 불가능하다. 대체 지표로 치환한다.

### 조사로 확정된 사실

- 카카오 이름·전화번호·이메일은 **비즈앱 전환**이 필요하다. 사업자등록증이 없어도
  본인인증만으로 전환 가능하고 이메일 승인 사례가 다수 있다. 다만 `name`·`phone_number`는
  카카오싱크 영역이라 승인 여부를 확답할 수 없다 → 승인과 무관하게 진행하는 이중 설계
- 소상공인365 상권 API는 `bigdata.sbiz.or.kr`이 아니라 **공공데이터포털(data.go.kr)**에서 신청
- 국가법령정보 OPEN API 인증키(OC)는 무료·자체 발급
- Auth.js 카카오 provider와 `@auth/pg-adapter`는 공식 지원

사용자 지시로 전부 삭제했다. 다음 구현은 pm 체계로 [[0916-infra]]부터 다시 시작한다
([[dev-workflow]]).

Docker 데몬은 미기동 상태다. 사용자가 Docker Desktop을 직접 실행해야 한다.

### 확인이 필요한 항목

확인 없이 임의로 정하지 않는다.

1. ~~`users` 테이블 이름 충돌~~ — **해결됨(2026-09-15).** 우리 테이블을 `app_users`로
   바꿨다. 근거는 [[database-design#해결됨 — 테이블 이름 충돌 (2026-09-15 확정)]]
2. **LLM 제공자 (09-20 전 필수)** — 차원은 `vector(1536)`으로 확정됐다. 두 후보
   (OpenAI `text-embedding-3-small`, Gemini `gemini-embedding-001`) 모두 1536을 낼 수 있어
   스키마는 막히지 않는다. 제공자만 고르면 되고 LLM은 임베딩과 같은 곳으로 묶는다
3. **리눅스 서버 사양·접속 방법·도메인 유무 (09-30 전)** — HTTPS가 없으면 카카오
   Redirect URI 등록이 막혀 **로그인 자체가 안 된다**
4. **Docker Desktop 기동** — 현재 데몬 미응답. 사용자가 직접 실행해야 한다
5. **수익 모델 (시점 미정)** — 최초 분석에서 기획의 최대 결함으로 지적됐으나 아직 없다.
   9월 범위 밖이지만 제품 방향을 바꾸는 요소라 추적 대상으로 남긴다
6. **발행받을 데이터의 형태 (시점 미정)** — 받는 즉시 분석해 적재 방식을 정한다
7. **AURA 대시보드 연동 방식 (10월)** — 파일/API/DB 공유 중 무엇인지 통합 문서에 없다
8. **대상 업종·지역 (10월)** — 법령·상권이 10월로 밀리면서 함께 미뤄졌다
